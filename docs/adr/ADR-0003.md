# ADR-0003: Selección de Estrategia Cloud para MediTriage

## Estado

Aceptado

## Contexto

MediTriage es una plataforma orientada a reducir los tiempos de espera de los pacientes mediante una clasificación rápida y eficiente de la urgencia médica.
Durante la fase de arquitectura se seleccionó una arquitectura Monolito Modular debido al tamaño del equipo, la complejidad actual del proyecto y la necesidad de desarrollar un Producto Mínimo Viable (MVP) de forma eficiente.
En esta etapa fue necesario definir una estrategia cloud que permitiera desplegar la solución, reducir la carga operativa del equipo y aprovechar servicios gestionados para infraestructura, almacenamiento, bases de datos e inteligencia artificial.

Los atributos de calidad definidos para el proyecto son:

- Seguridad
- Disponibilidad
- Rendimiento

---

## Alternativas Consideradas

### Azure

Proveedor cloud con servicios gestionados para bases de datos, almacenamiento, inteligencia artificial, despliegue y gestión de secretos.

### AWS

Proveedor cloud ampliamente utilizado con servicios equivalentes para bases de datos, almacenamiento y despliegue.

### Google Cloud Platform (GCP)

Proveedor cloud con capacidades avanzadas para análisis de datos e inteligencia artificial.

---

## Decisión

El equipo decide adoptar Microsoft Azure como proveedor cloud principal para el despliegue de MediTriage.

---

## Justificación

La elección de Azure se fundamenta en los siguientes criterios:

- Disponibilidad de servicios gestionados adecuados para las necesidades del proyecto.
- Reducción de la complejidad operativa.
- Facilidad para desplegar y escalar la aplicación.
- Integración con servicios de inteligencia artificial.
- Menor esfuerzo de administración de infraestructura.
- Alineación con los objetivos académicos y alcance del MVP.

---

## Servicios Gestionados Seleccionados

Con el objetivo de reducir la carga operativa del equipo y aprovechar las capacidades administradas por el proveedor cloud, se seleccionaron los siguientes servicios gestionados de Microsoft Azure:

### Azure Container Apps

Servicio utilizado para desplegar la aplicación MediTriage sin necesidad de administrar servidores o infraestructura física.

### Azure Database for PostgreSQL

Base de datos relacional gestionada para almacenar síntomas, historiales clínicos, usuarios y demás información operativa del sistema.

### Azure SQL Database Ledger

Servicio utilizado para mantener registros de auditoría verificables e inmutables, permitiendo dar soporte a los requerimientos de seguimiento y trazabilidad clínica.
 
### Azure Machine Learning

Servicio utilizado para alojar y administrar el motor de clasificación asistida basado en inteligencia artificial.

### GitHub Actions

Herramienta utilizada para automatizar procesos de integración continua, pruebas y despliegue del sistema.

---

## Consecuencias Positivas

- Reducción de la carga operativa del equipo al utilizar servicios gestionados.
- Mayor disponibilidad y confiabilidad de la infraestructura.
- Despliegues más simples y rápidos.
- Escalabilidad administrada por el proveedor cloud.
- Integración sencilla con servicios de inteligencia artificial.
- Mayor enfoque del equipo en el desarrollo de funcionalidades de MediTriage en lugar de la administración de infraestructura.

---

## Consecuencias Negativas
 
- Dependencia tecnológica de Microsoft Azure.
- Posibles costos asociados al uso de servicios gestionados en comparación con soluciones autoadministradas.
- Menor flexibilidad para migrar rápidamente a otro proveedor cloud.
- Algunas configuraciones avanzadas dependen de herramientas y servicios específicos de Azure.

---

## Trade-Offs

El equipo acepta una mayor dependencia del proveedor cloud a cambio de reducir significativamente la complejidad operativa y administrativa del proyecto.
Se privilegia la rapidez de desarrollo, la simplicidad de despliegue y la disponibilidad de servicios gestionados frente a una solución completamente autoadministrada.

---

## Decisión Final

El equipo adopta Microsoft Azure como proveedor cloud principal para MediTriage y utilizará servicios gestionados para soportar el despliegue, almacenamiento de datos clínicos, auditoría, automatización e inteligencia artificial del sistema.
Esta decisión permite reducir la complejidad operativa del proyecto y mantener el foco en el desarrollo del Producto Mínimo Viable (MVP).
